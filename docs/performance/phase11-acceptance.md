## 本轮修复

1. 同章重复定位会使旧原生 Range 端点退到仍连接的 `MAIN` 父节点。原 `isConnected` 检查误保留了空高亮；现检查非折叠端点和对应挂载块，并断言三个重叠绑定的原文逐字一致。
2. 按书籍/更新时间、位置顺序补充可重建组合索引；列表先物化分页实体键，再取 160 字符摘要及展示绑定。可见高亮增加 `afterId` / `nextCursor`，旧 offset 调用保持兼容；源票据、代及块范围逐页复核。
3. 同样式、同优先级共享 Chromium 绘制组；相同源区间共享带引用计数的 Range，每处绑定仍有独立身份、样式和点击路由。最后一个引用解除即释放；大型计算约每 8ms 让出，并在被新任务取代或关闭时取消。脏样式状态跨取消保留，避免新绘制组无 CSS。密集解绑/撤销、任务取代、六次连续取代的数据集上界、空组立即释放和绘制中关闭均通过断言。正式Schema版本不变，新增索引可重建；新旧offset协议仍兼容。
4. 恢复发布事务仅重读完整关系集合的轻量版本/状态来复核同一 binding epoch；相等才复用原完整快照，冲突仍保守 pending。语句按表预编译、相同章节快照复用序列化；原代+绑定同事务、CAS、失败回滚保持。
5. 两个旧测试预期已按已有阶段 9/10 契约修正：热缓存命中可零范围读取；完整未变原文证明可精确恢复旧绑定。这不改变目录行为或恢复决策。
