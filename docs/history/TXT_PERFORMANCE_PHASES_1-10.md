- 有效性契约包含实际文件身份、首/中/尾至多各 4096 字节的 `sha256-3x4096-v1` 采样指纹、编码/BOM、四类版本和解析配置 SHA-256 摘要。指纹只散列采样，不无条件计算整书哈希；元数据被保留且改动避开采样区仍可能漏检，完整校验/手动重建 UI 留在阶段 10。
- 所有坐标均为半开区间。byte 坐标相对物理文件，跳过文件头 BOM；UTF-16 坐标按仅去文件头 BOM、CRLF/CR→LF 的文本计算。章节间换行归属沿用阶段 1：下一节前的分隔换行不纳入上一节区间。正文起点在标题行换行后；前言/固定块从 section 起点开始。正文特征 v1 跳过空白首行，从首个非空白正文行提取前两个非空白 Unicode 码点；末尾特征取整个正文最后两个非空白码点，均不拆代理对。
- 支持 UTF-8、GBK/GB18030、UTF-16LE/BE，并兼容 ASCII 对应的 Windows-1252；BOM 优先。其他旧编码明确走原有内存解析路径，不声称命中持久索引；非法字节序列拒绝持久化。目录章/无标题前言/500 行 fallback 均保留。

### 阶段 3 实现与验证

- Kookit 源码提交：`3bd7455`；桌面单文件产物已同步普通入口。索引坐标/解析契约和 DDL 沿用阶段 2 的版本 1，已有有效缓存可直接热打开，无需全部重建。
- 支持编码的 open 只做文件身份/采样校验及 SQLite 索引加载，不返回原书 buffer；`TxtRender` 持有空 buffer，目录构建不读取章节正文。进入目标章时通过同一受控 `database-command` 的 read-chapter，按票据、可读代、章 ID/顺序和章内字节范围校验，每次最多 256KiB。主进程只读目标物理范围，读取前后核对实际文件身份/采样；失效新会话没有可读旧代，源变化则拒绝旧偏移。
- Renderer 对章节块使用有状态 TextDecoder，保留 UTF-8/GBK/GB18030/UTF-16LE/BE 的跨块字符与代理对，忽略文件 BOM 的处理只发生在建索引时；章节解码保留字面 U+FEFF，拼接后统一 CRLF/CR→LF，并校验规范化 UTF-16 长度。ASCII/Windows-1252 同样走随机路径；其余旧编码保留原内存适配，不宣称零整书读取。
- **阶段 3 当时的过渡路径：** 首次/失效/显式刷新通过 read-source 临时整书读取、解码和建索引，扫描后仅保留轻量元数据；复制元数据字符串，避免章节名子串间接保留整书。**该正常桌面冷建路径已由阶段 6 的有界 Worker 流式扫描替换**，不再是当前剩余实现项；旧适配器分支仍保留，实际内存稳定性仍须按最终矩阵验证。
- 桌面 TXT 导入不再执行自动 HTML ZIP 预缓存；手动/批量预缓存准备 SQLite 索引，已有 ZIP 不会绕过新阅读路径，也不据此跳过索引准备。清除缓存失效活动指针，不删除原文或笔记；已打开读者固定自己的不可变索引代，可继续读取。重建保留活动/上一代、会话固定代及未解绑正式绑定引用代；关闭源/Renderer 销毁仅解除会话固定，下次重建只能清理无剩余引用的旧缓存代。最多 128 个源会话，不以停留一页的时长过期，不长期持有文件句柄。
- 同章重复生成的 Blob 会替换旧 URL，提供 section unload 与关书 destroy；这只是本阶段所需释放，尚不宣称跨章 DOM/Blob/LRU 已有完整预算。**阶段 3 当时的超大单章整章组装已由阶段 7/8 的受支持窗口替换；兼容模式仍可能整章组装，完整生命周期与长期预算留在阶段 9。**

### 阶段 4 实现与验证

- Kookit 源码提交：`96effc1`，PDF 清理补丁 `06961be`，桌面产物已接入普通入口。复用原 `notes` 为 small/chapter/range 三类独立实体，正文/标题/标签/时间属于实体；`note_bindings`、`chapter_bindings`、`range_bindings` 保存位置，后两表用唯一约束限制每实体零或一个未解绑关系。没有自动父子关系。
- 独立 `annotation_schema` 版本 1；首次迁移先做 SQLite online backup（含 WAL），再事务化重建获授权的旧测试 Note 表。保留绘图到 `drawing_notes`，保留索引与其他表，失败回滚；重开正式库不运行旧 Note 字段迁移。未打开用户真实资料库。
- 全部操作通过受控 `database-command/annotations`。实体与绑定各自有版本比较；追加小绑定不改其他位置，换绑在同一事务中先解绑再建关系。单条/全部解绑保留正文及历史快照，可逐条撤销；旧代不可验证时撤销为待处理，不冒充有效。样式只更新当前绑定，不覆盖其他位置或正文。
- TXT 绑定由主进程验证票据/当前文件/有效索引代，保存独立 ID、章快照/文档版本、小摘录、前后文和正文相对 UTF-16 半开范围；校验代理对边界。章节/范围选择自身编辑页的章节框，范围必须同书同代、起止有序且包含全部中间章。非 TXT 小批注保留原格式定位适配，UTF-16 字段为空；绘图不混作选文实体。

### 阶段 6 实现与验证

- **扫描与兼容：** Kookit `txtStreamIndex.ts` 是纯数据扫描器，通过异步字节块单次物理遍历同时计算 LF 规范化 UTF-16 / byte 双坐标、标题/前言/500 行兜底、空标题降级、行数/权重和正文首尾特征。不积攒全文或全部章节；保留有界行探针及当前章节摘要。与原 v1 构建器对照覆盖 UTF-8、GBK/GB18030、UTF-16LE/BE、Windows-1252、BOM、CRLF/CR、1-byte 块、代理对、超长默认正文行及随机行边界；原 v1 契约/Schema 不变，旧有效缓存直接热开。

- **章内坐标：** `txtBlocks.ts` 随原 Worker 单次物理扫描生成可选索引头 `checkpoints: [physicalByte, normalizedUtf16][]`，每段物理范围最多 8KiB，优先在后半段换行处结束，巨长段仍硬切块；不切编码字符、UTF-16 代理对或 CRLF。坐标只含数字，沿用 `txt_index_schema`/解析契约 v1，不改内容或绑定表、章 ID、原文/批注坐标语义。主进程严格校验单调性、间距、完整首尾和大小，并只持久化白名单数字；旧有效索引不强制失效。旧内存构建器亦产出同样坐标，五种编码与流式输出逐字符对照。章入口直接下标，章内块二分定位，不扫描或解码前面的正文。
- **共同预算：** 初始按当前章 ±2 补充；短章不足预读视口时可连续补多个，硬上限共同约束为 **24 章、24 块、128Ki UTF-16 字符、20,000 DOM 节点（包含文本节点）**（满足最先到达的限制），不是以固定五章代替巨章分块。每个窗口最多一个活动范围请求，复用带票据/代/章 ID/文件验证的 `read-chapter`；单块最多 8KiB，滚动/rAF 计算窗口，预读约前 1/后 2 个视口，无全书正文缓存。会话/不可变代固定，目标 token 丢弃迟到挂载、跳过过期排队请求；关闭时移除本窗口的观察器、监听器、rAF、DOM 和待挂载引用。阶段 9 的统一跨格式生命周期、60 分钟/千跳内存门槛没有据此提前结项。
- **锚点与选区：** 前插/回收用原文文本节点及字符锚点补偿；ResizeObserver、字体 loadingdone 及采样前尺寸校验覆盖字号/宽度/延迟布局的时序，防止新布局覆盖旧锚点。选区覆盖的块暂时钉住，达到共同预算则停止扩展（`stats.selectionLimited`），保留已有选区；收起选区后恢复回收/预读，不能无限增加钉住块。普通跨章选区/复制已由阶段 8 覆盖；超出窗口的选区仍受该预算约束，不承诺跨整书常驻选择。
- **记录与兼容：** 保存可选 `txtWindow: {version:1, chapterId, generation, offset}`，offset 为章内规范化 UTF-16；Viewer 保留该字段进入恢复链，位置持久化及当前章标识用现有 leading/trailing throttle，滚轮原型不再经过 sleep(200)/边界清 body。旧记录的 count 是 DOM 段落序号，绝不当字符偏移；原型暂保留同章起点安全降级，**阶段 8 现已提供旧记录章内适配**，具体兼容边界见下一节。阶段 7 当时的默认关闭路径不变，跨代/章 ID 不匹配拒绝套用坐标；当时未接高亮及新绑定，阶段 8 已补齐这些窗口交互。
- **自动验证：** Kookit 47 项相关回归、两库类型检查、桌面引擎/纯扫描器及 Koodo 生产构建通过；Koodo Vitest 14、主进程诊断 7、原生索引 22（另加检查点损坏断言）、Worker/ASAR/故障矩阵 17、原生批注 21、目录 UI 12、原菜单/批注 UI 18、Worker 首屏/导入 UI 8，以及默认路径冷/热阅读通过。新增 `test/txt-window.electron.cjs` 的 23 项检查使用正常编译引擎、实际 IPC、隔离 SQLite/合成 121 章（末章含 600 万 UTF-16 的单段正文），覆盖双向各跨 100 章、深跳取消、跨章选区/预算钉住、字体/窗口变化、原文锚点、失败保留 DOM、新记录冷/热恢复及关书清理；以 JSON 报告核对，不把 Electron 启动当作通过。
- **性能与未测门槛：** 自动断言巨章 80% 深处跳转及热恢复各自正文读取 <256KiB、单次范围 ≤8KiB、最大并发 1；窗口阶段 Blob 创建与整书 read-source 次数均 0。数字属于隔离合成测试，不是实书 P95、真实磁盘或长期内存成绩。原生系统剪贴板/菜单完整手动体验、延迟外部字体文件、真实主样本及 6.1/7.1 完整矩阵仍待测；changes/新版云、原文缺失入口、阶段 8–11 的剩余要求继续保留。既有自定义正则每行 65,536 单元限制不变，超长单段回归使用默认解析器。

- **设计修订：** 对受支持的普通 TXT 连续滚动会话，首次使用旧有效缓存时，在挂载前通过 `ensure-blocks` 请求现有流式 Worker **一次性补充可重建加速元数据**。这取代初版不补齐且继续单章的策略。仍为一个 iframe、自然连续流和有界预读；章边界不触发显式 jump、不替换 body、不将下一章标题置顶，不接管/重新合成滚轮手势。只有目录/书签/搜索等显式跳转才走 jump。支持范围及 24 块/24 章/128Ki UTF-16/20,000 节点预算不变。
