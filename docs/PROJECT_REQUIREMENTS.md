## 1. 项目目标与范围

- **目标平台**：Windows Electron 桌面版，主要阅读约 100 MB 以内的大型 TXT 小说。
- **主要目的**：围绕小说建立**小批注、章节批注、大批注**，核心是「阅读时记、重读时查、写作时找回原文」。
- **基础原则**：优先保留阅读流畅性和正式数据安全；复用 Koodo 的原书库、选文/复制、目录、书签与阅读记录。**不创建独立小说项目文件夹、原文副本或第二套数据库**。
- **不在本期**：标签输入与标签管理、批注二次编辑、统一批注管理、全书库/跨书查询、复杂搜索筛选排序与批量操作、引用关系、复杂草稿/回收站/预览工作区。旧 UI 方案不作为本轮开发依据；不删除已有底层字段和数据。

## 4. 当前批注 UI 的核心规则（摘要）

完整开发范围、操作流程和验收要求以 [批注 UI 专项需求](ANNOTATION_UI_REQUIREMENTS.md) 为准。本节只保留不能误解的原则：

- 三类批注独立，**新建界面只有批注正文及必要的绑定章节/范围，没有标题、标签或内部分类**；**所有类型的二次编辑暂不开发**。标签及原有绑定等底层数据不能为精简界面而删除。
- **小批注**：选中文字后的**横向菜单**新建，底部居中输入。绑定当前选中的单章原文位置；不新增“仅高亮”或“添加到已有小批注”的新流程。
- **章节批注**：阅读正文**右键纵向菜单**新建，自动绑定右键所在章节；同一章节允许多个独立批注。
- **当前章节批注查询面板**：只在“小批注 / 章节批注”两个分类间切换，**不包含大批注**；只读查看、原文定位，跨章节跳转复用“返回原处”。
- **大批注**：在第一阶段完成后才开发，右键新建，起止章初始化为当前章节，可调整一个连续章节范围。中间参考资料区只读展示范围内的小批注与章节批注。
- 有效小批注绑定的原文在正常阅读时以下方细密虚线/点线提示；从查询面板主动定位时临时高亮。不因此新增纯高亮批注实体。
- **布局硬约束：侧面板与小说正文必须在同一个阅读工作区内作为同层并列区域布局，不得绝对定位或悬浮覆盖正文。** 章节编辑与当前章节查询是“正文 2/3 + 面板 1/3”；大批注是“正文 1/3 + 参考 1/3 + 编辑 1/3”；右侧窄工具栏始终独立在最右侧，比例不包含工具栏。小批注底部居中快速输入是例外，不属于侧面板。
- 不因本轮缩小 UI 范围破坏三类实体与绑定、无绑定批注的存储、备份恢复和正式数据。

## 5. 当前批注 UI：两阶段开发计划

**执行策略：逐项开发、逐项由用户体验确认后再继续，禁止一次性铺开整套界面。** 旧 UI-0～UI-7（标签作用域、统一管理、三类型当前章列表、二次编辑等）计划已废止，不得继续按其实施。

| 阶段 | 顺序 | 开发内容 | 验收重点 |
|---|---|---|---|
| **第一阶段** | 1 | 阅读界面最右侧固定窄工具栏（目录、当前章节批注、阅读设置） | 工具栏与阅读工作区相互独立，面板打开后仍常驻 |
| 第一阶段 | 2 | 小批注新建 | 选文横向菜单、底部居中加宽输入、正文与原文绑定、保存/取消 |
| 第一阶段 | 3 | 章节批注新建 | 右键纵向菜单、点击位置判定章节、**同层的正文 2/3 + 编辑 1/3** |
| 第一阶段 | 4 | 当前章节批注查询 | **只显示小批注/章节批注**；顶部双向切换；**同层的正文 2/3 + 查询 1/3**；定位与返回原处 |
| **第二阶段** | 5 | 大批注新建 | 必须在第 4 项完成后；右键创建、连续章节范围、**同层三栏** |
| 第二阶段 | 6 | 大批注参考资料查询 | 与大批注三栏一起使用；自动展示范围内的小批注/章节批注、范围变化刷新、详情只读 |

**严禁把章节批注编辑面板、当前章节查询面板、大批注参考资料区或大批注编辑区做成浮动覆盖层。** 需要让正文容器真实缩窄，而不是在原文上叠放面板。验收时必须检查布局关系和实际鼠标/滚动交互，仅截图看似分栏不算通过。

每步开发前检查当前真实代码并优先复用现有能力；若需要新接口先说明原因。阶段完成后记录“已实现 / 自动验证 / 用户实测 / 待测”，不得将旧测试结果冒充本轮 UI 验收。

## 6. 数据安全、性能与开发约束

- **正式批注不可清空**：旧测试 Note/高亮的清理授权仅适用于**阶段 4 首次迁移之前**且已使用完毕。已有 `annotation_schema` 的库、新建批注、绑定、原文、绘图、书签、阅读进度必须保护。
- 数据库操作只通过 `database-command` IPC，不在 Renderer 直接操作 SQLite；新增查询必须受控。书籍与正式用户数据仍在 Koodo 原书库。
- 不能用全书批注正文缓存掩盖性能问题；批注列表分页/虚拟化、详情按需读取，章节选择不得一次渲染几千选项。
- 修改涉及 Kookit 时，只编辑源码并正常构建对应桌面产物，不直接读取混淆/压缩库文件猜实现。
- 开发前核对两个仓库分支/HEAD/工作区与远端差异；保留无关改动。实现后按影响范围运行自动测试及人工实书验证，记录**已实现 / 自动验证 / 用户实测 / 待测**。
- 默认仅提交到当前工作分支，不强制推送、改写历史或直接提交主分支；需要远端更新时按当前授权及 `AGENTS.md` 执行。
- Windows 使用 `yarn.cmd` / `npm.cmd`；常用 `yarn.cmd dev`、`yarn.cmd typecheck`、`yarn.cmd test`、`yarn.cmd build`。完整 Electron/Node/Kookit 回归命令参见 [技术细节文档](TXT_IMPLEMENTATION_DETAILS.md#1-项目范围与环境)。
