### 阶段 3 实现与验证

- Kookit 源码提交：`3bd7455`；桌面单文件产物已同步普通入口。索引坐标/解析契约和 DDL 沿用阶段 2 的版本 1，已有有效缓存可直接热打开，无需全部重建。
- 支持编码的 open 只做文件身份/采样校验及 SQLite 索引加载，不返回原书 buffer；`TxtRender` 持有空 buffer，目录构建不读取章节正文。进入目标章时通过同一受控 `database-command` 的 read-chapter，按票据、可读代、章 ID/顺序和章内字节范围校验，每次最多 256KiB。主进程只读目标物理范围，读取前后核对实际文件身份/采样；失效新会话没有可读旧代，源变化则拒绝旧偏移。
- Renderer 对章节块使用有状态 TextDecoder，保留 UTF-8/GBK/GB18030/UTF-16LE/BE 的跨块字符与代理对，忽略文件 BOM 的处理只发生在建索引时；章节解码保留字面 U+FEFF，拼接后统一 CRLF/CR→LF，并校验规范化 UTF-16 长度。ASCII/Windows-1252 同样走随机路径；其余旧编码保留原内存适配，不宣称零整书读取。
- **阶段 3 当时的过渡路径：** 首次/失效/显式刷新通过 read-source 临时整书读取、解码和建索引，扫描后仅保留轻量元数据；复制元数据字符串，避免章节名子串间接保留整书。**该正常桌面冷建路径已由阶段 6 的有界 Worker 流式扫描替换**，不再是当前剩余实现项；旧适配器分支仍保留，实际内存稳定性仍须按最终矩阵验证。

当前支持编码的桌面 TXT 正常链路：`viewer → database-command(open) → 异步实际文件身份/有界采样校验 → notes.db 有效索引命中 → sections/toc → 目标章受控异步字节范围读取 → 章节流式解码/统一 LF → HTML/Blob → iframe`。缓存缺失/失效或显式刷新时，`prepare → 合并任务/Worker 单次流式扫描 → 主进程 building 批次 → 验证与 CAS 原子发布 ready/active → 返回轻量索引`；期间可显示临时文本预览，正式目录及深位置恢复等待 ready。导入持久化书籍后也后台调用准备服务。普通支持编码桌面路径不调用 read-source 或传输整书；Web/无新宿主协议及未支持编码仍保留旧内存适配。

阶段 8 后，具备块坐标的受支持普通 TXT 滚动会话默认将显示后半链路改为 `目标章/块坐标 → read-chapter 有界范围 → 块解码 → 同 iframe 文本窗口 → 可见块绑定查询/原生 Range 高亮`。旧有效索引缺块坐标、变换/辅助阅读等兼容条件仍用单章链路，不因此自动重扫或更改绑定代。

当前实现与仍待处理的约束：

- 持久索引具有 byte/规范化 UTF-16 双坐标；支持编码按目标章异步随机读取。冷重建已使用 Worker 有界字节/元数据批次，不经整书 Renderer buffer/字符串；支持会话使用有界正文块；兼容单章路径的巨章仍整章组装，不能对旧缓存/变换模式宣称全部已窗口化。
- 文件选择优先书库内文件，其次外部引用路径；有效性校验须检查实际读取的文件。
- 桌面 TXT viewer 不读旧 ZIP，导入不再自动生成 TXT ZIP，手动/批量缓存准备持久索引；未支持编码保留旧适配。导入原有的读文件、MD5、保存原文流程仍存在，不宣称首次导入零全文读取。
- 桌面 `handleHighlight` 已按当前章/有效代查询绑定，返回摘录定位与正文存在标志，不加载完整批注正文；详情打开编辑器时读取。TXT 单章使用逐行映射，窗口使用逐块精确映射，不把 Rangy body 字符计数当原文坐标。阶段 8 已为旧卡片/导航提供有界分页摘要与按需详情；阶段 5 目录虚拟化保持不变。
- 兼容单章路径切章仍清空 body；受支持窗口绕过该导航并维护一个有界文本窗口。通用跨格式 Blob/DOM/缓存与长期资源预算仍按阶段 9 验收。
- 现有五库为 `books.db`、`notes.db`、`bookmarks.db`、`words.db`、`plugins.db`。索引表与正式批注表均已具备生产入口的惰性初始化；Agent 自动测试只使用隔离库。不能据此推断用户实际默认/自定义资料库是否已在自行运行时迁移；后续以实际 Schema 为准，已有正式标记不得重置。
- 新数据库操作统一走受控 `database-command`，不能直接在 Renderer 操作 SQLite。现有 `custom-database-command` 和旧 registry 只认识旧表，不照搬任意 SQL 或结果转换假设。
- 未改造的旧表仍使用原迁移；正式 annotations 标记存在时跳过旧 Note 迁移，防止重开库添加旧位置列。新增 TXT/批注表采用独立版本事务及一致备份。连接缓存按实际数据库路径区分。
- 新版备份以 `config/annotations.v1.json` 恢复正式批注；同包旧 notes.db 不经旧转换器覆盖正式表。旧 Note 云同步已停用，新多绑定云契约另行实现；本地章节缓存不进入批注清单。

## 4. 目标：持久索引与按需正文

正常开书目标：**实际文件身份/轻量校验 → SQLite 目录 → 目标章/块随机读取 → 有界正文窗口**。文件未变化不得重扫全文、整书解码或无条件计算完整 SHA-256。

- 复用现有 SQLite：阶段 2 已在 `notes.db` 固定本地索引 DDL；阶段 4 继续在同库增加绑定表，便于原子切换。不新建独立数据库。
- 索引是可重建本地缓存，不参与笔记云同步；原始 TXT 是唯一正文来源，不存整书 HTML 或正文副本。
- 元数据至少包括 book_id、实际文件身份、大小/mtime、采样指纹及算法、编码/BOM、parser_version、index_version、规范化/特征版本、解析配置摘要、indexed_at、document_revision、active generation。
- 章节至少包括 chapter_id、book_id、generation、chapter_index/name、起止及正文起始的 byte/UTF-16 两套偏移、first_chars、last_chars、行数、大小及识别类型。章 ID 与顺序分离；无批注章不要求跨重建保留 ID。
- 字节区间相对物理文件，文本区间按去文件头 BOM、CRLF/CR→LF 后的 UTF-16 单元计数，均为半开区间；显式处理 UTF-8、GBK、UTF-16LE/BE、块边界、多字节/代理对、空行和尾换行。
- 特征 v1：first_chars 跳过空白正文行，在首个非空白正文行取前两个非空白 Unicode 码点；last_chars 取整个正文最后两个非空白码点。不含标题，不足两个码点取实际值，避免拆分代理对。空白行和码点规则已固定在原 v1/流式扫描器对照测试中，不能跨实现漂移。
- 文件/编码/解析配置/版本变化或手动强制重建时才扫描。采用 building/ready 代及短事务切换，扫描/正文匹配在事务外完成；失败保留旧索引和全部批注。旧文件已被覆盖时不可用旧字节偏移读取新文件。
- 采样校验不能保证检测到元数据被保留且修改发生在未采样区的情况；阶段 10 仍须提供面向用户的手动完整校验/安全重建入口（尚未实现），不宣称现有抽样等于完整内容证明。内部显式刷新协议不等于完整校验 UI 已完成。
- 首版不要求整章 BodySha256、章节相似度、段落 diff 或任意拆章/合章自动迁移。

## 5. 三类批注与绑定

三类实体独立，分类/内容各自管理；可按章节互查参考，不建立自动父子关系，也不因其他类型删除而改变正文。大批注后续提供参考资料区 + 正文编辑区。

| 类型 | 数据与入口 |
|---|---|
| 小批注 | 直接改造原生 Note/notes；正文、标签、时间等在实体，一对多 `note_bindings` 保存各位置。选文→原菜单/编辑弹窗流程保持；追加位置为“添加到小批注→选择已有实体” |
| 章节批注 | 零或一个章节绑定，不含文字区间；在自身编辑页通过章节框选择/解绑，不用阅读区“添加到批注”入口 |
| 大批注 | 零或一个连续范围绑定；自身编辑页选择起始/结束章，含所有中间章。允许清空整个范围，禁止离散多选或删除中间成员 |

通用规则：

- 实体与绑定分离，解除一条/全部绑定不删除正文；无绑定仍可检索、编辑和分类。原“删除笔记”保留删除实体的语义，“解绑”是独立操作，提供撤销或等效恢复。
- 小批注单个锚点必须完整位于一个章节，可多位置、跨不同章节；允许不同锚点交叠/嵌套。纯高亮可表示为空正文实体 + 绑定。
- 每条绑定保存独立 ID、当前状态及最新章节快照（章 ID/名称、正文首尾特征、顺序/文档版本）；小绑定另存精确摘录、章内相对 UTF-16 范围、前后文及本处高亮样式。大范围保存两端各自快照和顺序边界。
- 点击高亮传 note_key + binding_id；正文/标签属于实体，位置样式属于当前绑定。列表一实体一项，无绑定不能消失。非 TXT 继续通过格式定位适配，不能伪造 TXT 坐标；现有格式绘图记录不能混作选文小批注。
- 手动换绑先解除要替换的旧关系，再建立新关系并更新快照。增加小绑定不删除其他绑定。不设自动/手动优先级或手动保护标记。
- 正文、摘录和锚点是正式用户数据，需要新版备份/恢复；索引是缓存。新版云同步契约须单独实现，不能把多绑定压成旧单位置 Note 或同步本地章节缓存。

### 文件变化后的恢复

以下是**阶段 10 尚未实现的目标**；当前重建保留旧快照/正文并把旧有效关系转为 pending，仅保留已有手动绑定能力，不执行下述自动恢复。

重新索引仍扫描全书，但只对未解绑绑定引用的旧章节做身份恢复，只读取相关候选章正文；无批注书籍直接重建。

1. 小批注：章名匹配 + 原文摘录存在才确认；章名不匹配时要求正文首尾特征同时匹配，并仍须找到摘录。重复原文用上下文/相对位置消歧；无法唯一确认则待处理，找不到原文则失效。
2. 章节批注：唯一章名优先，否则首尾特征同时匹配；重名、空/弱特征不能任意选章。
3. 大批注：分别匹配两端，验证新代中同书、顺序及连续范围；任一端缺失、歧义或反转则整个范围待处理，不部分恢复。
4. 成功后事务化更新到最新有效快照/位置；失败保留旧快照与正文。已解绑关系不参与恢复。后台恢复须用版本比较避免覆盖用户并发换绑。

旧项目仅作设计参考：`linglin-911/FujiyNotepad`，分支 `feature/reader-settings-phase4`。核心文件在 `src/FujiyNotepad.Core/`：`NovelAnnotations.cs`、`NovelChapterIndexBuilder.cs`、`NovelChapterIndexReconciler.cs`、`AnnotationAnchorMetadata.cs`、`AnnotationAnchorQuoteLocator.cs`、`NovelAnnotationStore.cs`。旧 BigAnnotationChapters 用有序关联表并校验连续性；本项目可用起止章模型，不能照搬旧项目文件体系和级联删除关系。

- **风险/回滚：** 中文长标题行高、滚动定位与展开状态。先限定 TXT 适配，可按开关恢复旧组件，数据库不变。

### 阶段 6：Worker 后台索引与首次可读优化

- **作用/边界（实现状态见第 2 节，以下保留验收计划）：** 将首次打开、文件变化或显式重建的全文读取/解码/章节扫描移到后台线程，保持 Renderer 和主进程可响应；正常 SQLite 索引热命中不启动全文扫描 Worker。普通切章继续按需读取目标正文，不为每次翻章重新启动全书扫描。
- **仓库/文件：** Koodo 拟新增 `utils/main/txt-index-worker.js`、任务管理器；Kookit 提取纯扫描逻辑，不依赖 DOM；仅在确需打包 worker 资源时做最小构建改动并记录理由。
- **链路：** 首次/变化/手动重建 → worker_threads 扫描 → 有界元数据批次 → 主进程索引 store；正常缓存命中不启动扫描 Worker。
- **迁移/旧数据：** 无数据库引擎变化，主进程仍拥有 SQLite 写连接，Worker 不直接写同一 notes.db；遵守 database-command 数据库入口。
- **步骤：** 取消、进度、每书任务合并、背压；从文件句柄分块读取，不把全书字符串来回 structured clone；第一章边界完成可提供临时首屏，完整代 ready 后再开放完整目录。无有效旧索引时的首次深位置恢复，必须扫描到目标或完成索引，不承诺凭字节猜章。
- **测试/验收：** 导入中关闭/换书、两窗口同书、索引中改文件、Worker 崩溃、正则超时、批次慢消费、生产打包后资源位置；UI 可交互且无整书 ArrayBuffer 复制。
- **收益：** 全文 O(N) 工作离开 Renderer/主进程事件循环，首次首章尽早可读；总扫描复杂度不变。Worker 本身不保证总耗时或峰值内存下降，需同时落实分块读取、有限批次/背压和取消；连续滚动及边界衔接由阶段 7/8 完成。
- **风险/回滚：** 打包与共享模块约束。先实现串行任务服务再替换执行器，可退回同协议扫描器；缓存数据结构不变。

### 阶段 7：TXT 一个 iframe 的连续滚动窗口

- **仓库/文件：** Kookit `TxtRender.ts`、`GeneralRender.ts`、`navigationUtil.ts`、`layoutUtil.ts`，拟新增 `txtWindowManager.ts`；Koodo `reader/mouseEvent.ts` 和 viewer。
- **链路：** 当前边界 sleep(200) → prev/next → 清 body；改为 scroll/rAF 可见窗口计算 → 提前读相邻章 → 同 Document 容器增删。
- **迁移/旧数据：** 不改内容/绑定表；阅读位置先保存章 ID、代、章内位置并保留旧记录适配。仅 `TXT + readerMode=scroll` 启用。
- **步骤：** 一个 iframe 中独立 data-chapter-id 容器；初值当前±2 章，上限由块数/字符量/DOM 节点预算共同限制；接近边界预加载，可连补多个短章；前插/回收以稳定原文锚点补偿视口。对超大单章再按段落分块，不能仅以“最多五章”声称 DOM 有界。
- **测试/验收：** 双向跨 100 章、短章连跳、快速反向、深跳取消旧请求、字号/窗口变化、字体延迟加载、超大单章、跨章选区和复制。选区覆盖块时可临时钉住必要块，但达到预算时要有明确行为，不能无限禁止回收。
- **收益：** 已预加载章节自然进入滚动流，避免清空 body 等待；DOM 随窗口预算而非已读章数增长。
- **风险/回滚：** 前插跳动、CSS 范围污染、异步过期写回。按会话/代/目标请求 token 防止过期挂载；单书开关退回单章模式，数据库不变。

### 阶段 8：批注、高亮、阅读进度适配

- **仓库/文件：** Koodo viewer.handleHighlight、databaseService、noteUtil、popup/menu、store/recordLocation；Kookit `getHighlightCoords`、`renderHighlighters`、`noteUtil.ts`、`navigationUtil.handleRecord`。
- **链路：** 以阶段 4 已有的单章/有效代绑定查询、单章原文↔DOM 映射与按需正文为基线，扩展到多章可见块查询、容器内映射和增量高亮；把单章 body 假设改为视口章判定。全书完整批注正文查询已从正常恢复路径移除，不重复实现。
- **迁移/旧数据：** 必要时追加读进度版本字段（旧占位 M4，实际版本按落地顺序分配）；保留旧 cfi/xpath/count，优先新章 ID+相对偏移，旧数据按适配恢复；不把估算 HTML size 当原文准确坐标。
- **步骤：** 延续已有工作区分页与详情按需读取，补齐旧导航/摘要列表的有界查询及多章窗口适配；章节和范围批注通过关系查询；按块增量高亮，不能每次清空整个 doc 的高亮；选区和菜单事件只绑定一次。高频 scroll 用 rAF，记录用仓库 throttle，章 ID/索引前缀查表。
- **测试/验收：** 多章同屏、重叠/嵌套高亮、同一 Note 多绑定、跨章原生选区复制、选择菜单位置、点击高亮打开正确实体与当前绑定、书签/TTS/搜索跳转，以及窗口缩放后位置恢复；新小批注跨章范围拒绝不影响普通复制。
- **收益：** 批注查询/DOM 工作与窗口内绑定数相关，避免每章 IPC 搬完整书批注正文。
- **风险/回滚：** 文本映射和当前绑定识别最敏感。阶段 7 的原型在这些回归通过前不默认启用；失败可关闭连续窗口并保留新 Note 模型，不删关系。

### 阶段 9：Blob、DOM、缓存和资源生命周期

- **仓库/文件：** Kookit `html.ts`、`TxtRender.ts`、`GeneralRender.removeContent`、`layoutUtil.handleOneChapterDoc`、window manager；Koodo viewer 清理函数和 before-reader-close。
- **迁移/旧数据：** 无 Schema；退休索引 GC 只能清可重建且无当前引用代，不清用户绑定快照。不得常规开书执行全库 VACUUM。
- **步骤：** URL 一处拥有者；load 去重，最后消费者完成后 release/revoke，异常与取消亦释放；优先内部直接文本接口，原 section.load/unload API 保持兼容。正文 LRU 按字节预算，预加载并发有上限；关书取消任务、释放 fd/Worker、监听器、定时器、观察器、全文引用与缓存。
- **测试/验收：** 故障注入后 active URL/句柄/观察器计数归零；10 次开关书、1000 次跳章、连续阅读 60 分钟；比较稳定期 JS heap/私有内存曲线，不能用 RSS 一次不回落证明泄漏。
- **收益：** 长时间阅读资源受预算约束，避免每章 Blob 与任务累积。
- **风险/回滚：** 过早 revoke 造成 fetch 失败，LRU 回收选区。引用计数/消费者 token 管理；可单独回退缓存策略，保留明确释放。

### 阶段 10：文件变化后的恢复与安全重建

- **仓库/文件：** Koodo index/binding store、拟新增 `txt-reconcile-service.js`、恢复结果 UI；Kookit 仅共享纯文本匹配帮助函数，旧项目代码不直接搬运。
- **链路：** 文件变化 → building 代 → 活跃绑定快照 → 新目录候选 → 候选章随机读取 → 摘录消歧 → 短事务切换。
- **迁移/旧数据：** 使用 M1/M2，不覆盖失败快照；此阶段只处理切换后创建的新 Note/绑定。若需新增 reason/版本字段（旧占位 M3），按实际落地顺序分配迁移版本，仅追加，不就地重写用户正文。
- **步骤：** 实现本文匹配决策、范围双端校验、任务合并、binding_epoch/CAS、取消、事务失败恢复和强制重建入口。
- **测试/验收：** 无批注改文件、章首尾错字、同名番外、重复摘录、摘录删除、标题改名、章插入/删除/重排、两端反转、单端缺失、全部解绑后改文件、手动换绑与后台重建并发。失败及歧义场景错误自动绑定数必须为 0，批注正文/数量保持。
- **收益：** 重建代价以全文索引 O(N) + 引用候选正文量为主；不遍历所有历史章进行复杂指纹映射。
- **风险/回滚：** 两字特征碰撞多；重复正文不能猜。保守 pending；旧代与 changes 在切换验证后保留，恢复操作在当前文件重新验证后执行。

### 阶段 11：大量批注与最终压力验收

- **仓库/文件：** 两库测试；Koodo 拟新增隔离 Electron 性能脚本和数据生成器，扩充现有诊断；性能结果写 docs，不提交小说正文。

### 7.1 完整测试矩阵、指标与发布门槛


以下数值是建议验收目标，不是已经获得的成绩。首次建立同设备基线后可调整时间预算，但数据安全和无整书热打开扫描属于硬门槛。

| 缓存命中 | 72.6MiB，1/1600/6800 章重复打开各 20 次 | 全文扫描/整书解码/完整 SHA-256 次数均 0；读取量=有界采样+目标窗口；建议首屏 P95 ≤1.5s |

| UI 与其他数据 | 新 Note/高亮/书签/进度/选择/复制/菜单 | 原笔记操作流程不变；新批注内容零丢失；书籍/书签/进度保留；旧测试笔记不纳入保留验收 |
| 备份 | 旧备份书库等数据→新程序、新版笔记备份→新程序，合并/重试 | 新实体/分类/绑定/摘录完整往返；旧测试笔记可跳过；缓存可重建；恢复不清已有新数据 |
